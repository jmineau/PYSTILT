Configuration#

config.yaml is blocks, each a field of ProjectConfig:

mets:
  hrrr: /path/to/hrrr_arl
models:
  hysplit: {n_hours: -24, numpar: 200}
stages:
  footprint:
    class: stilt.footprint.FootprintStage
    grid: {xmin: -113.0, xmax: -110.5, ymin: 40.0, ymax: 42.0, xres: 0.01, yres: 0.01}
variants:
  hrrr: {}
  hrrr-long: {n_hours: -72}
  hrrr-coarse: {stages: {footprint: {grid: {xres: 0.05, yres: 0.05}}}}
  hrrr-particles: {stages: {footprint: null}}
execution:
  backend: local
output: output

mets names the meteorology (for HYSPLIT, HysplitMetConfig). models names the transport models, each block with that model’s settings (HysplitConfig for hysplit). stages names what is made from each simulation’s particles: the footprint, with the footprint settings (FootprintConfig). A stage’s block is named for its stage, so the footprint’s is footprint, the name of its folder in the output directory and of its column in project.status(). variants says what runs, and execution where (ExecutionConfig). Each class lives next to the code that uses it (stilt.footprint.config, runtraj.execution.config, runtraj.models.hysplit), and all but the transport model’s are importable from stilt.

No setting sits at the top level. One written there is refused with a message that names its block, such as 'n_hours' is a hysplit setting. Write it under models: hysplit:. A key may be written once in each block: YAML would keep the last of two, so PYSTILT refuses the file and names the line of the second. Each page below lists its fields with their defaults and is generated from the code.

Tip

New to PYSTILT? The Projects and variants guide covers the few settings most projects need. This page lists all of them.

Every key#

These tables are generated from the code, so they always match the installed version.

Top level#

The blocks, and where the results go.

Parameter

Description

Default

mets

Meteorology by name, such as hrrr: the folder of its files, or a mapping of its settings. At least one is required. Each is checked by the met config of the transport model that reads it (runtraj.models.hysplit.HysplitMetConfig for HYSPLIT).

{}

models

Transport models by name, each a block of its settings: the defaults of every variant that runs it. A block named hysplit is that built-in model. Any other model class gets a block of any name that gives its import path as class, such as class: mypkg.models.MyModel. A model has one block. Left out, the project runs HYSPLIT with its defaults.

{'hysplit': {}}

stages

What is made from each simulation’s results after the transport model runs, by name, each a block that gives the stage’s import path as class and then its settings. A block is named for its stage: PYSTILT’s footprint, for example, is the block footprint with class: stilt.footprint.FootprintStage. A stage runs for every variant, unless the variant sets it to null. Left out, the project makes particles only.

{}

variants

Variants by name, each a set of overrides of the defaults. A variant’s own keys are met (needed with several mets unless the variant has a met’s name), model (the name of its models block, needed with several), realizations (run N times, realization k with seed + k, as one ensemble), and stages (a stage’s settings to change, by the stage’s name, or null for a variant without it). Every other key is a setting of its model. Variants with the same transport settings share one transport model run and differ in what their stages make from it. At least one is required: hrrr: {} runs the defaults.

{}

execution

Where the releases run and with what resources, such as backend: slurm and its options.

ExecutionConfig(backend='local', local=LocalConfig(cpus=1, fetch=True), slurm=SlurmCo...

output

Directory the results go to, relative to the project directory unless absolute. A URL such as s3://bucket/output puts it on an object store. Several projects can name the same directory and share runs.

'output'

HYSPLIT#

The keys of the hysplit block under models:, the transport model’s settings (HYSPLIT Integration). They are the defaults of every variant that runs HYSPLIT, and a variant may override any of them by writing the key itself. Left out, the block is HYSPLIT with the defaults below, which are HYSPLIT’s own. n_hours has no default, and capemin, kblt, kmixd, krand and vscales are unset unless given: HYSPLIT chooses them when it runs. stilt init and stilt.Project.init() write STILT-R’s values where they differ (stilt.project.STILT_R_HYSPLIT; the list is in Coming From STILT-R).

Parameter

Description

Default

n_hours

Length of each simulation, in hours. Negative runs backward in time. It has no default: a config must say it.

Required

seed

Random seed for a reproducible run. Different seeds give different runs. Requires krand: 2. HYSPLIT 5.1.0 ignores the seed under krand 4 and 10 to 13, and under 1 uses it only for the initial turbulent velocity. Must be 0 or more: runtraj writes it to SETUP.CFG as -(seed + 1), because HYSPLIT reseeds its generator only from a negative value and gives every SEED of 0 or more the same stream, so a seed and its negative would give the same run. Realization k of a variant runs with seed + k, so realization 0 shares the unperturbed run’s seed.

None

mode

What HYSPLIT makes: particles, the particle table; concentration, grids of each pollutant’s concentration (grids and pollutants); or trajectory, the trajectory table, from HYSPLIT’s trajectory program hyts_std.

'particles'

pollutants

The pollutants of a concentration run, each released at every release location and counted on every grid. At least one in mode: concentration; none otherwise.

[]

grids

The grids of a concentration run. At least one in mode: concentration; none otherwise.

[]

conversions

The conversions of a concentration run with ichem: 2, each from one of pollutants to another. At least one with ichem: 2; none otherwise.

[]

ichem

HYSPLIT’s ICHEM, which in mode: concentration changes what a run counts: 0 concentration (the default); 1 a grid for each release location; 2 pollutants that convert (conversions); 5 deposition of whole particles by probability; 6 mass divided by air density; 9 a lowest level that follows the mixed layer; 10 a grid for each emission cycle (qcycle). The particles mode is ICHEM=8, the only value it takes, and a trajectory run reads none.

None

numpar

Number of particles released per simulation. More particles sample the turbulence better and take longer to run.

2500

directory

The HYSPLIT folder as unpacked: runtraj runs exec/hycs_std under it and reads the data tables (ASCDATA.CFG, LANDUSE.ASC, ROUGLEN.ASC, TERRAIN.ASC) from its bdyfiles/. Unset, the first hycs_std on PATH runs, with the tables of a bdyfiles/ folder beside its folder; runtraj includes neither. The SHA-256 of hycs_std and of each table is part of each run’s settings, so runs of different builds are kept apart.

None

varsiwant

Particle variables hycs_std writes to the trajectory output, by the lowercase four-letter names HYSPLIT reads. Each is a column of the particles under the same name, except indx, time, long, and lati. zcfx is the vertical displacement by convective flux along the trajectory, in m. The default is HYSPLIT’s own list of 20.

['time', 'indx', 'long', 'lati', 'zagl', 'sigw', 'tlgr', 'zsfc', 'temp', 'samt', 'foo...

capemin

Convection option. -1 turns convection off, -2 uses the Grell scheme, and a positive value mixes vertically when CAPE exceeds it, in J/kg. Unset, HYSPLIT chooses -2 with ICHEM=8.

None

cmass

Compute grid concentrations (0) or grid mass (1). Read only for HYSPLIT’s concentration grids (mode: concentration), where 1 makes each cell hold mass, not mass per volume, and counts no deposition at z = 0.

0

conage

Particle age at which particles and puffs convert, in hours, when initd is 3 or 4.

24

cpack

Packing of the binary concentration grid: 0 every point, 1 only nonzero points. Unset, HYSPLIT chooses 1. Read only for HYSPLIT’s concentration grids (mode: concentration), where 2, one point per grid, is refused: runtraj does not read its file.

None

delt

Integration time step, in minutes. 0 lets HYSPLIT choose; a negative value sets the minimum step. With ICHEM=8 HYSPLIT always steps 1 minute, so this setting has no effect.

0.0

dxf

Horizontal x offset factor for HYSPLIT’s meteorological ensemble.

1.0

dyf

Horizontal y offset factor for HYSPLIT’s meteorological ensemble.

1.0

dzf

Vertical offset factor for HYSPLIT’s meteorological ensemble (0.01 is about 250 m).

0.01

efile

Name of a time-varying emissions file. Blank uses none.

''

emisshrs

Duration of the particle release, in hours.

0.01

frhmax

Maximum horizontal puff-rounding parameter. Used only for puffs, when initd is not 0.

3.0

frhs

Horizontal puff-rounding fraction for merging. Used only for puffs, when initd is not 0.

1.0

frme

Mass-rounding fraction for enhanced puff merging. Used only for puffs, when initd is not 0.

0.1

frmr

Mass-removal fraction for enhanced puff merging. Used only for puffs, when initd is not 0.

0.0

frts

Temporal puff-rounding fraction. Used only for puffs, when initd is not 0.

0.1

frvs

Vertical puff-rounding fraction. Used only for puffs, when initd is not 0.

0.01

hscale

Horizontal Lagrangian timescale, in seconds.

10800.0

initd

Initial distribution: 0 3D particles, 1 and 2 3D puffs, 3 and 4 puffs horizontally and particles vertically. Other values are HYSPLIT’s conversions and special modes.

0

k10m

Use the 10 m winds and 2 m temperature as the lowest meteorology level (1) or skip them (0).

1

kagl

Trajectory heights above ground (1) or above sea level (0). Read only by HYSPLIT’s trajectory model, not by hycs_std. In mode: trajectory runtraj always writes 1, and refuses another value.

0

kbls

Derive boundary-layer stability from surface fluxes (1) or from wind and temperature profiles (2).

1

kblt

Boundary-layer turbulence scheme: 1 Beljaars, 2 Kantha-Clayson, 3 TKE, 4 measured variances, 5 Hanna. Unset, HYSPLIT chooses 5 with ICHEM=8.

None

kdef

Horizontal turbulence from vertical mixing (0) or wind deformation (1).

0

khinp

Age, in hours, given to particles read from pinpf. 0 keeps their own age.

0

khmax

Maximum particle age, in hours. HYSPLIT drops a particle older than this.

9999

kmix0

Minimum mixed-layer depth, in meters. 0 by default in mode: trajectory, as in hyts_std.

150

kmixd

Mixed-layer depth source: 0 from the meteorology, 1 from the temperature profile, 2 from the TKE profile, 3 from a modified Richardson number. Unset, HYSPLIT chooses 3 with ICHEM=8.

None

kpuff

Horizontal puff growth: linear (0) or empirical (1). Used only for puffs, when initd is not 0.

0

krand

How HYSPLIT draws the random numbers for turbulence. 0, or unset, picks 2 when numpar is 5000 or less and 1 otherwise. 1 uses a precomputed table. 2 draws them during the run and is the only mode that uses seed. 3 uses no random numbers (a diagnostic mode). 4 draws them during the run from a clock-based seed, so every run differs; there are about 5000 possible seeds. 10 to 13 are modes 0 to 3 with a random initial seed. HYSPLIT does not check this value and other values silently break the turbulence, so runtraj rejects them.

Footprint grids#

Longitudes count modulo 360, so a grid across 180° can be written xmin: 170, xmax: 190 or xmin: 170, xmax: -170, and the footprint’s longitudes are then 170 to 190. An xmax west of xmin is read as crossing 180° when the two are on either side of 0° or one is written past 180°: with both in one hemisphere (xmin: -110.5, xmax: -113) they are taken to be swapped and the grid is refused. A grid spans at most 360°. A particle cloud on both sides of 180° is measured as one cloud for the smoothing. A grid that goes all the way around (xmin: -180, xmax: 180, with cells that fit 360°) is a circle, so smoothing that passes the east edge returns at the west edge. On a grid that ends at or near 180°, particles just across 180° smooth onto the grid, as particles just past any other edge do.

Projected grids (a crs such as EPSG:32612) keep their bounds in degrees and take xres and yres in the projection’s units. The grid covers the whole box in the projection, so on a wide or polar box it reaches past the box’s projected corners, where the curved edges bow out. A grid that stilt.Mesh.to_grid() picks for a projected geometry covers every one of its areas. A grid of more than a billion cells is refused, which catches a resolution in degrees on a grid in meters. The two steps that depend on the cell size work in the grid’s units. The smoothing kernel’s width is worked out in degrees and converted, so a footprint is smoothed about as much on 1 km UTM cells as on 0.01° cells. The early-time interpolation, which adds particle positions between output steps in the first 100 minutes when the particles move more than a cell per step, runs on 100 m UTM cells as it does on 0.001° cells. STILT-R Parity says where STILT-R differs on these grids.

Time layers (tres) are recorded one way, so 60min is recorded as 1h and two spellings of one length share a settings folder. Each layer holds the influence of the particles in its minutes, so the layers sum to the same total footprint whatever tres is.

Loading config.yaml does not read a geometry file. PYSTILT reads it once, when it works out the variants’ settings, and picks the grid then (stilt.Mesh.to_grid()), so a variant with a geometry cannot change only part of the grid (grid: {xres: 0.1} under its stages). A grid given with a geometry is used as given. Each footprint file stores a code for the geometry it was made for, which is how foot.stilt.aggregate knows when a mesh no longer matches.

Footprint maps#

To show each footprint on a web map, add a block for the map stage after the footprint’s (MapStage, which needs the visualization extra). Its keys are the color scale, the same for every image so that two hours compare by eye:

stages:
  footprint:
    class: stilt.footprint.FootprintStage
    grid: {xmin: -113.0, xmax: -110.5, ymin: 40.0, ymax: 42.0, xres: 0.01, yres: 0.01}
  map:
    class: stilt.footprint.MapStage
    vmin: 1.0e-5
    vmax: 0.1

Each release gets <release id>.json in the map’s folder of the output directory, written after its footprint. It holds the footprint summed over time as a PNG data URL (image), the image’s corners as [[south, west], [north, east]] (bounds), the release, its time in UTC, the color scale and the footprint’s units. The image’s rows are spaced as on a web map, so Leaflet places it with L.imageOverlay(entry.image, entry.bounds). An empty footprint gets a file with image and bounds null. A footprint grid across 180° is drawn as any other: its bounds run east past 180 ([[-5, 170], [5, 190]] for a grid from 170 to -170), which Leaflet draws in the right place. The map stage draws longitude/latitude footprints only: on a projected grid (crs in the footprint’s grid) its map fails with an error saying so.

Parameters#

The settings that shape a run’s particles belong to the transport model, and are written in its block under models: (hysplit when the config has no models). HYSPLIT’s are in runtraj.models.hysplit.HysplitConfig, under HYSPLIT’s names (see HYSPLIT Integration). Each model’s block holds all of its settings, the ones PYSTILT reads itself among them (n_hours and seed): nothing passes from one model’s block to another’s.

What is done with the particles afterwards is the footprint stage’s, under stages: footprint:, and does not change the particles or their settings folder: hnf_plume, the near-field correction, applied when the footprint is made, and footprint_depth, pbl_height and pbl_height_min, which say how PYSTILT computes foot when the footprint needs one (The Particle Table). HYSPLIT computes its own foot with veght, a HYSPLIT setting. A footprint made from that foot reads veght for the near-field correction, so a footprint_depth written for it must equal veght; a different one is refused, saying to set veght, or pbl_height so that PYSTILT computes foot.
