Execution#

Most users only need project.run(), project.submit(), or stilt run (Running). The functions below do the work underneath.

  • run() is what project.run() calls. It finds the releases with missing results, runs them, and waits until they finish. task=(i, n) runs share i of n here (task_share()), which is what stilt run --task i/n does.

  • submit() is what project.submit() calls. It writes a job array script (job_script()) whose tasks each run stilt run --task, submits it with sbatch, and returns the job id at once.

  • run_particles() runs the transport model for one Simulation and writes its particles and log.

  • run_stages() runs the stages of the variants that share those particles, the footprint among them: each stage file that is missing, in the order the stages read one another, and each again when what it reads was made again. run_stage() runs one, which writes its own file.

  • run_release() runs every variant of one release, skipping what exists. Variants that share particles run the transport model once and run their stages on the particles in memory. A failure is recorded with the simulation (stilt.Simulation.failure). Workers are always handed releases.

  • run_releases() runs a list of releases, in this process or in a process pool.

On Slurm each task of the job array runs one share of the releases (task_share()) with stilt run --task. A local run happens in this process. A program that starts the tasks itself, on another scheduler, writes pending() to the releases.txt each task reads (stilt run --releases); wait() waits for a Slurm job array by its id.

Transport model#

The worker runs a simulation through the transport model its settings name. HYSPLIT is the one built in that runs, and CONTRIBUTING describes how to add another, named by its import path. PYSTILT’s stilt-r model (class: stilt.migration.StiltRModel) is one of those, and runs nothing: its variants read the runs stilt.migration.import_stilt_r() imported from STILT-R, with the settings STILT-R’s files record. A model fails a run that its meteorology does not cover, as MET_COVERAGE. Particles that all leave the met’s domain before the end of the run are a complete run.

Stages#

A stage makes one file per release from a simulation’s results, after the transport model runs. The footprint is one (stilt.footprint.FootprintStage). A stages block of config.yaml names its stage’s class by import path, so a stage in a package of your own needs no registration, and CONTRIBUTING describes how to write one. Use check_stage() in its tests.

runtraj.stages.Stage

What is made from each simulation's results: one file per release.

runtraj.stages.get_stage

Return the stage whose class is at the import path path, made with no arguments.

runtraj.stages.ordered

Return the names of stages in the order they run: each after the stages it reads.

runtraj.stages.check_stage

Check that stage keeps the promises the worker and the output directory rely on, for one config.
