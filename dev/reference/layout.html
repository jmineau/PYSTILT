Output Layout#

This page describes the files in an output directory, so that a reader in R, Julia, DuckDB, or plain pyarrow can read them without PYSTILT. In Python, stilt.read_particles(), stilt.read_footprint(), and stilt.Project.footprints() do all of this for you.

The folders#

Each kind of result has its own tree: particles/ for what the transport model wrote, and one named for each stage of the project, which is what is made from a simulation’s results afterward. The footprint is a stage, and its tree is footprint/. Inside a tree, each settings folder holds the results of one set of settings, split by the release’s date:

<output>/
  particles/
    settings=hrrr-7d36c8/
      _settings.yaml
      date=2024-07-15/<release id>.parquet
    settings=hrrr-err-b2399e/                 an ensemble
      _settings.yaml
      realization=0/date=2024-07-15/<release id>.parquet
      realization=1/date=2024-07-15/<release id>.parquet
  footprint/
    settings=hrrr-f82d40/
      _settings.yaml
      date=2024-07-15/<release id>.parquet
  logs/
    settings=hrrr-7d36c8/date=2024-07-15/<release id>.log
    settings=hrrr-7d36c8/date=2024-07-15/<release id>.failure.yaml
    settings=hrrr-f82d40/date=2024-07-15/<release id>.failure.yaml
  scratch/
    settings=hrrr-7d36c8/date=2024-07-15/<release id>/

A settings folder is named <variant>-<six characters>. The variant is the name in config.yaml that first made the folder, and the six characters are the start of its settings hash (below). The date is the release’s release date in UTC. An ensemble (realizations: N) has a realization=k folder between the settings folder and the dates.

The logs/ tree follows the folders of the results:

  • <release id>.log is the transport model’s log, under the particles’ settings folder.

  • <release id>.failure.yaml says why a result failed, and at which stage. A failed run writes it under the particles’ settings folder, with stage: particles. A failed footprint writes it under the footprint’s own settings folder, with stage: footprint, since the particles were fine. It is removed when the result is written.

scratch/ holds kept workdirs, one folder per simulation, under the particles’ settings folder. A failed run’s workdir is kept, and with keep_workdir: true under execution: every run’s is.

The particles/ and footprint/ trees hold only Parquet files and _settings.yaml, so each reads as one dataset. A stage from another package has a tree under its own name, with files in the format and with the extension that stage chooses.

A simulation is complete when the model’s output file exists, and so does the file of every stage its variant uses: for a variant with a footprint, the particle file and the footprint file. A footprint with no cells is still a file (below), so it is complete.

_settings.yaml#

Every settings folder holds a _settings.yaml. A particles folder’s:

name: hrrr
hash: 7d36c80b3b5a1a33cc355998f5755de469f61c53151a9d1b953fa698c81cd51f
pystilt: 0.1.0a23
model_version: hysplit.v5.1.0
settings:
  capemin: -1
  # ... every transport parameter, in name order
  met:
    crop: null
    source: HRRR
  model:
    data_files:
      ASCDATA.CFG: fd489592654bf600fd96b08d2ccde76f90f0672b7e872fb9fa33dd363fbaa643
      LANDUSE.ASC: de63b2e3f405cdecbe2f4599ba276bf21b5bb05d786cd54e9c24a051c42b8511
      ROUGLEN.ASC: a8503953877b09e906e85364e4081c43ffb5d7353e3ffdb259094acbb95588b1
      TERRAIN.ASC: 0608b518d39ca63fe8774aef887f71f451b1c698c4b708bead36eb926ab86268
    name: hysplit
    sha256: 37346bee81a62f31d2f273c9813d53a76c54d59cfd5adbf3f76a7f870e3f49f9
  n_hours: -24
  # ...

A stage’s folder, such as a footprint’s, names its stage and what its files were made from:

name: hrrr
hash: f82d40aea8c29b2a30b99b1c5a74166937ee4eef5df20aa80407bfb69a3ab7a0
stage: footprint
class: stilt.footprint.FootprintStage
reads:
  particles:
    folder: hrrr-7d36c8
    hash: 7d36c80b3b5a1a33cc355998f5755de469f61c53151a9d1b953fa698c81cd51f
versions:
  pystilt: 0.1.0a30
settings:
  cells_per_target: 4
  geometry: null
  geometry_hash: null
  grid:
    crs: +proj=longlat
    xmin: -112.5
    xmax: -111.5
    xres: 0.01
    ymin: 40.25
    ymax: 41.25
    yres: 0.01
  smooth_factor: 1
  transforms: []
  tres: 1h
name

The variant that made the folder.

hash

The folder’s settings hash, a SHA-256 in hex. The folder name ends in its first six characters.

pystilt

In a particles folder, the PYSTILT version that wrote the folder.

model_version

In a particles folder only: the version the transport model’s build reports, such as what hycs_std prints when it starts. It is not in the hash: model.sha256 is.

settings

What the results were made with. In a particles folder, the transport model’s parameters, met (the weather product and its crop), and model (the transport model and its build: the SHA-256 of hycs_std, and of each of HYSPLIT’s data tables). An ensemble adds ensemble: true, and realization k ran with seed + k. In a stage’s folder, the stage’s own settings: for a footprint, the footprint settings, with the grid.

stage, class

In a stage’s folder only: the stage’s name, which is also its tree, and the import path of its class, as config.yaml names it.

reads

In a stage’s folder only: what its files were made from, each with the name and the hash of its settings folder. particles is always there; a stage that reads another stage’s files lists that stage too.

versions

In a stage’s folder only: the PYSTILT version that wrote the folder, and the version of the stage’s own package when it is another one.

A particles folder’s hash covers its settings block. A stage folder’s hash covers its settings block together with the hash of each thing under reads, so the same footprint settings on other particles give another folder. The versions are not part of a hash. Every particle and footprint file records its folder’s full hash as runtraj:hash.

Particle files#

A particle file is particles/settings=.../date=.../<release id>.parquet, one row per particle per output step. The Particle Table describes what each column means.

Column

Stored as

Notes

release

dictionary of string

The release id, the same on every row.

int32

int32

Minutes since release, negative for a backward run. Read back as float64.

Footprint files#

A footprint file holds only the cells that are not zero:

Column

Stored as

Notes

release

dictionary of string

The release id.

hour

int16

The layer, counted from the release time in layers of tres: hours, by default (below).

y

int16

The cell’s row in the grid, 0 at ymin.

x

int16

The cell’s column in the grid, 0 at xmin. So a stored footprint’s grid has at most 32,767 columns and rows; a wider one is refused.

foot

float32

The footprint value, in ppm per (µmol m⁻² s⁻¹).

The file’s metadata:

Key

Value

runtraj:release

The release as JSON.

stilt:footprint

The footprint settings as JSON, with the grid: the settings block of the folder’s _settings.yaml.

stilt:hours

Every layer of the footprint, a JSON list such as [-24, ..., -1]. It includes layers with no cell left, so a dense array has len(stilt:hours) layers.

stilt:name

The variant that made the footprint.

stilt:empty

true when no particle reached the grid, else false.

runtraj:hash

The folder’s settings hash.

stilt:particles_hash

The settings hash of the particles it was made from.

stilt:pystilt

The PYSTILT version that wrote the file.

runtraj:realization

The realization number, in an ensemble only.

An empty footprint is a file with no rows and stilt:empty set to true. A file without the key is not empty. An empty footprint is complete: the run worked, and nothing reached the grid. Treat it as missing, not as a footprint of zeros.

The hour#

Layer k holds the particles’ influence from k to k + 1 layers after the release time, and is stamped at its start. A layer is tres long, an hour by default, so the stored hour is the hour unless the settings give another length; it is always the layer number. stilt.Project.footprints() turns it into the unit tres is written in, and names its dimension for it: layer -1 of 15min layers is minute -15 there. A particle row at age minutes falls in layer floor(age / m), where m is tres in minutes. For a release at 18:30 on a backward run with hourly layers:

Particle age (minutes)

Layer

Covers

-1 to -60

-1

17:30 to 18:30, stamped 17:30

-61 to -120

-2

16:30 to 17:30, stamped 16:30

The layers keep the release’s minute, so a release at 18:30 has layers starting at half past. With tres: 15min its layer -1 covers 18:15 to 18:30 and layer -2 covers 18:00 to 18:15. With tres as long as the run (1D for a 24-hour run) there is one layer, -1, stamped at the start of the run, which holds the whole run.

The grid#

x and y index the grid in stilt:footprint (or the folder’s _settings.yaml):

  • The number of columns is floor((xmax - xmin) / xres), and likewise for rows. A partial cell at the edge is dropped, so xmax = -110.505 with xmin = -113 and xres = 0.01 gives 249 columns.

  • Column i is centered on xmin + (i + 0.5) * xres, and row j on ymin + (j + 0.5) * yres. Row 0 is the southern edge.

  • On a projected grid (crs other than +proj=longlat) the bounds are degrees and the resolution is in the projection’s units. Only the corners (xmin, ymin) and (xmax, ymax) are transformed to the projection, and the cells are laid out between them.

For example, in pyarrow:

import json

import numpy as np
import pyarrow.parquet as pq

table = pq.ParquetFile(path).read()
meta = table.schema.metadata
grid = json.loads(meta[b"stilt:footprint"])["grid"]
hours = json.loads(meta[b"stilt:hours"])
nx = int(np.floor((grid["xmax"] - grid["xmin"]) / grid["xres"] + 1e-9))
ny = int(np.floor((grid["ymax"] - grid["ymin"]) / grid["yres"] + 1e-9))
foot = np.zeros((len(hours), ny, nx), dtype="float32")
layer = {h: i for i, h in enumerate(hours)}
t = [layer[h] for h in table["hour"].to_pylist()]
foot[t, table["y"].to_numpy(), table["x"].to_numpy()] = table["foot"].to_numpy()

The small tolerance keeps the last whole cell when the bounds are decimals that binary floats store a little short. Layer h starts h times tres after the release time. tres is in stilt:footprint, written as minutes (15min), hours (1h) or days (1D); a file that does not record it has hourly layers.

Units#

Footprint values are in ppm per (µmol m⁻² s⁻¹), ppm m2 s umol-1. The files do not say so; stilt.read_footprint() adds the units to the array it returns.

Release ids and the release#

A release id is the release time to the minute, then the location:

202407151830_-111.85_40.77_5            a point: lon_lat_altitude
202407151830_-111.85_40.77_X0-3000msl   a column: lon_lat_X<bottom>-<top>
202407151830_multi_7bb3ffdc53           a multipoint: a hash of its points

A location ends in msl when its heights are above sea level. Whole numbers are written without a decimal point.

runtraj:release holds the whole release as JSON. Its time keeps the seconds, and is UTC with no time zone:

{"kind": "point", "time": "2024-07-15T18:30:00", "altitude_ref": "agl",
 "longitude": -111.85, "latitude": 40.77, "altitude": 5.0}

{"kind": "column", "time": "2024-07-15T18:30:00", "altitude_ref": "msl",
 "longitude": -111.85, "latitude": 40.77, "bottom": 0.0, "top": 3000.0}

{"kind": "multipoint", "time": "2024-07-15T18:30:00", "altitude_ref": "agl",
 "longitudes": [-111.85, -111.86], "latitudes": [40.77, 40.78],
 "altitudes": [5.0, 10.0]}

Reading many files#

Read as a dataset with hive partitioning, a tree gives the folder names as columns: settings, date, and in an ensemble realization. DuckDB (hive_partitioning = true), polars, R’s arrow, and pyarrow.dataset all do this. A reader of one file gets only the stored columns. Footprints And Particles has DuckDB examples.

Keys you do not know#

A reader should skip metadata keys and _settings.yaml keys it does not know. Later versions may add some, and files rewritten from development builds may still carry old ones, such as an empty stilt:empty_reason.

Which rules a file follows#

A file follows the rules of the PYSTILT version that wrote it: stilt:pystilt in a result file, and pystilt in a _settings.yaml (under versions in a stage’s folder). There is no separate format number. This page describes the files of the current version, and the list below says when a rule changed.

  • 0.1.0a23: the first release with this layout. Results moved from simulations/by-id/ to the output directory, particles and footprints are Parquet files in settings folders, and an empty footprint is marked stilt:empty. Files from development builds before it carry a version ending in .dev..., and may differ.

  • After 0.1.0a29: footprints are in footprint/ (it was footprints/), the tree named for their stage. A stage folder’s _settings.yaml has stage, class, reads and versions in place of particles, particles_hash and pystilt, and a failure record says stage where it said step. The footprint files themselves are unchanged. Footprints stored by an earlier version are not found, and a run makes them again from the stored particles.

Why the output has separate trees#

The output directory keeps results, logs, and kept workdirs in separate trees (particles/, footprint/, logs/, scratch/). Each results tree holds result files only, so pyarrow, DuckDB, polars, and R read particles/ or footprint/ as one table, and a log or a failure record beside a result would break that. Whether a simulation is complete is read from the results trees alone; the logs tree only explains the ones that are not.
